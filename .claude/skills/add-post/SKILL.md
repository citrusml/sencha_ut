# 活動記録を追加する

CLAUDE.md の「記事（_posts）のルール」「画像」に従う。ここではその手順と、間違えやすい点を書く。
進めるのは PR の作成まで。**マージはしない**。マージはユーザーの指示を毎回待つ。

## 1. 受け取るものを確認する

- 日付・原文・写真がそろっているか確認する。足りなければユーザーに聞く。
- 原文の最後に文責（`（T.T.）` のようなイニシャル）がないときは、記事を作る前に、意図的かどうかをユーザーに確認する。文責をこちらで足したり推測したりしない。
- タイトルやタグなど原文にないものは、こちらで補う（報告の仕方は 4 を参照）。

## 2. ブランチを作る

```bash
git fetch origin
git switch -c post-YYYY-MM-DD origin/main
```

## 3. 写真

**入手する**
- チャットに貼られた画像は、セッションの images フォルダにあるファイルを使う。
- URL（Discord など）で渡されたときは、まず `curl -sI` でファイル名・種類・サイズだけを確認する。そのうえでダウンロードしてよいかユーザーに聞き、許可が出たら scratchpad の新しいフォルダに保存する。
  - Discord のリンクには期限がある（URL の `ex=` が期限の UNIX 時刻を16進数で表したもの）。期限がいつかも伝える。

**縮小する**
- ImageMagick を使う。`magick` が PATH になければ `C:\Program Files\ImageMagick-*\magick.exe` を使う。
- 横長の写真:
  ```bash
  magick 元.jpg -auto-orient -resize "1800x1800>" -quality 80 出力.jpg
  ```
- 縦長の写真: 長辺 1800px だと幅が 1400px（記事写真の目安）を下回るので、`"2000x2000>"` にする。
- 縮小後のファイルが元より重くなる、または元がすでに目安の範囲内で画質が下がるだけのときは、元のファイルを使う。
  - どちらを使うか迷ったら、同じ部分を切り出して横に並べた比較画像を作り、見比べて決める。
    ```bash
    magick \( A.jpg -crop 500x400+X+Y \) \( B.jpg -crop 500x400+X+Y \) +append 比較.png
    ```
  - ファイルの重さは、既存の記事写真（`assets/images/posts/` に 600〜850KB のものもある）を目安にする。

**置いて、メタデータを消す**
- 置き場所は `assets/images/posts/YYYY-MM-DD.jpg`。同じ日に複数枚なら `_1`, `_2` を付ける。
- 置いたら、次の順に処理する。
  1. `perl tools/strip_metadata.pl report <ファイル>` で確認する。
  2. `(none)` 以外なら `strip` で消す。
  3. もう一度 `report` して `(none)` を確かめる。
- 何を消したか（特に GPS・撮影日時）を報告する。何もなかったときも、そう報告する。

## 4. 記事ファイルを作る

- `_drafts/template.md` の front matter に沿って、`_posts/YYYY-MM-DD-スラッグ.md` を作る。
- **本文は原文を一字一句、改行の位置も含めてそのまま貼る。** 文責者がいるため、手を入れると著作上の問題になる。
  - 言い回しの修正、段落の分け直し、空行の追加、絵文字の追加もしない。
  - 表示で気になる点があっても、直さずに提案するだけにする。たとえば、改行が1つだけの箇所はサイト上では段落がつながって表示される。
- front matter の各項目とファイル名のスラッグには妥当な値を入れる。そのうえで、**入れた値をすべて表にして報告する**。
  - 各項目について、原文やユーザーの指定から取った値か、こちらで補った値かを書く。補った値には理由も一言添える。
    | 項目 | 値 | 出どころ |
    |---|---|---|
    | layout | post | 固定 |
    | title | 桜茶ときんつば | 補った（原文の主題から） |
    | date | 2026-04-25 | ユーザー指定 |
    | image | /assets/images/posts/2026-04-25.jpg | 日付から |
    | tags | [お稽古, 本日のお菓子] | 補った（お菓子の紹介のため） |
    | ファイル名 | 2026-04-25-kintsuba.md | 補った |
  - 補った値はユーザーが変えられるように、PR を出す前に確認を取る。

## 5. 確認する

- `bundle exec jekyll build` がエラーなしで終わることを確かめる。
- プレビューで記事を表示する。
  - `preview_start` で `jekyll` を起動し、`/YYYY/MM/DD/スラッグ.html` を開く。
  - 4000 番ポートでサーバーがすでに動いていることがある。その場合は、そのサーバーで記事の URL を開く（自動更新つきで同じフォルダを見ている）。
  - 本文は `get_page_text` で、写真はスクリーンショットで確かめる。
- ユーザーが自分で文面を直せるように、記事ファイルをファイルのペインで開く（`show_pane` の `file`）。
  - ユーザーが直したあとは、変わったのが改行や空行だけか、本文の文字も変わったかを確かめ、それを報告する。直した内容を元に戻さない。

## 6. コミットと PR

- ユーザーの確認が終わってから進める。
- `git add` は記事と画像だけにする。
  - `.claude/launch.json` などの無関係なファイルは含めない。
  - pre-commit フックを止めない（`--no-verify` は使わない）。
- コミットメッセージは日本語にする。
- push して、PR を出す。
  ```bash
  gh pr create --repo citrusml/sencha_ut --base main
  ```
  - PR の説明には、補った項目と、写真の処理内容（元のサイズ、縮小したかどうか、メタデータの確認結果）を書く。
- マージはしない。PR の URL を報告して、ユーザーの指示を待つ。
